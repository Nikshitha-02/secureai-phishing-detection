### Mismatch 1: Typosquatting – rn→m substitution

**Expected:** Dangerous  |  **Detected:** Suspicious  |  **Score:** 60

**Reasoning note:** arnazon normalises to "amazon" via rn→m substitution; "login" impersonation keyword in hostname; "signin" in path. Layer-2 near-match fires → brandImpersonation +35, keywords +10 (action combo +20, hyphen-action combo +5). Total ≥ 71.

### Mismatch 2: Typosquatting – rn→m substitution (space breaks detection)

**URL:** `https://rnicrosof t-account.com/password-reset`

**Expected:** Suspicious  |  **Detected:** UNPARSEABLE  |  **Score:** N/A

**Reasoning note:** Space in URL makes it unparseable or yields a different hostname; the URL parser will likely reject it or treat it oddly. Expect Safe/Suspicious from parseUrl returning null → treated as unparseable → engine returns null. Marked Suspicious as a reasonable fallback expectation for the note — but this URL is primarily a parse-rejection edge case.

## Methodology

- **Rule engine only** — no Gemini AI, no Supabase, no network requests
- **Labels assigned by reasoning** — expected levels were determined by manually
  tracing scoring weights in `riskScoring.ts` before running the detector
- **Some labels are intentionally aspirational** — a few tests are marked with
  a higher expected level than the engine currently produces, to document
  known detection gaps (e.g. brand-in-path-only, punycode IDN homographs)
- **Failures ≠ bugs** — many failures indicate architectural limitations
  (no punycode decoding, no content inspection, no WHOIS) that are already
  documented in the README as known limitations

## Known Limitations Exercised by This Suite

1. **Brand in path only** — the engine checks the hostname for brand names;
   a brand appearing only in the URL path does not trigger impersonation detection
2. **Punycode / IDN homographs** — the engine does not decode punycode hostnames;
   IDN homograph attacks that arrive as `xn--...` are not caught
3. **Port numbers** — the engine has no port-based penalty;
   non-standard ports do not contribute to the risk score
4. **Action words in domain name** — ACTION_KEYWORDS are checked on path/query only;
   a hostname like "bank-transfer-verify.tk" does not get keyword points
5. **Unregistered brands** — "bank" is not in BRAND_REGISTRY;
   generic bank-impersonation domains without a registered brand name score lower
